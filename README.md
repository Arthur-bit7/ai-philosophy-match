# 同题 · ai-philosophy-match

两个人，一道题，多一种理解。一个无需注册的双人哲学与价值观讨论工具。

## 已实现的体验

1. 房主填写昵称，选择预设问题或自定义问题，创建双人房间。
2. 将邀请链接或 12 位房间号发给朋友；加入者自动获取同一道题。
3. 双方独立选择选项、填写文字，或两者一起使用。提交后本轮答案锁定。
4. 双方提交后揭晓原文与比较结果；在此之前，服务端不会向另一人返回你的回答。
5. 房主开启下一轮，双方自动同步题目；保留本房间的历史讨论，可下载纯文本记录。

支持桌面和手机布局。刷新当前标签页可恢复身份；断网后自动重连。轮询每次完成后等待约 1.8 秒，不会堆积请求。

## 立即运行

需要 **Node.js 22 或更新版本**，建议使用 Node.js 24。应用运行时没有第三方依赖，也不需要数据库或 API Key。

下载或克隆仓库，在仓库目录运行：

```bash
npm start
```

打开 <http://localhost:3000>。Windows 也可双击仓库中的 **start.cmd**。

本机模拟两个人时，使用两个独立浏览器窗口（例如普通窗口和无痕窗口）。不要复制一个已加入房间的标签页：浏览器可能复制该标签页的会话身份。

### 邀请其他设备

- **同一 Wi-Fi / 局域网**：在 Windows 运行 `ipconfig` 找到电脑的局域网 IPv4 地址。先用 `http://该地址:3000` 打开应用，再创建房间、复制邀请链接。需要允许局域网访问该端口。
- **不同网络的朋友**：将这个 Node 服务部署到支持长期运行进程的平台，使用同一个 HTTPS 网址。`localhost` 地址不能发给异地朋友直接使用。
- 这是有后端状态的应用，**不能仅上传到 GitHub Pages 等静态托管平台**。

## 比较方式

### 本地模式（默认）

不向外部 AI 发送数据。使用 `Intl.Segmenter` 对中文和英文分词，再计算词语集合的 Jaccard 重合度；选项相同与否单独呈现。

**词语重合度不等于观点相近度。** 例如“支持”和“不支持”可能使用很多相同词语。页面明确说明局限，不把这个数字当作政治立场判断。任意一方只有选项、没有可分词文字时，显示“文字不足”，不生成误导性的百分比。

### OpenAI（可选）

房主在“比较方式”中选择 OpenAI，可填写自己的 API Key 和模型名；也可由部署者提供服务器环境变量。双方都需要确认允许发送题目和回答，才可以使用 AI 房间。

返回本题观点相近度、依据、共同点、分歧和后续讨论问题。提示词限定为比较明确表达的观点，不根据回答给个人贴政治身份或人格标签。AI 结果仍可能不准确。

- 固定调用 `https://api.openai.com/v1/chat/completions`，不接受用户提供的自定义服务器地址。
- 请求不携带昵称、房间号或会话令牌，设置 `store: false`。
- 20 秒超时；网络、鉴权、限流或输出格式错误都会回退本地比较，并在页面说明。
- 重复提交不会重复触发模型调用。
- 模型输出通过结构校验，页面将所有用户和模型内容当作文本显示。
- API Key 只在服务器内存中保存至房间过期，不通过房间接口返回、不写入浏览器存储或应用日志。它会通过请求发送给所用服务器，因此在线使用时需要 HTTPS。
- 若配置服务器共享 Key，任何能访问服务的房间创建者都可以选择使用它。面向公开互联网部署时，请在网关增加访问控制和费用额度限制。

GitHub Models 已于 2026-07-30 停用，因此本版本移除了旧的默认 GitHub Models 接入，旧的 `GITHUB_TOKEN` 等变量不再使用。见 [GitHub 官方说明](https://docs.github.com/en/github-models)。OpenAI 接口格式参考 [官方 API 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

### 环境变量

复制 `.env.example` 为 `.env`，按需填写，再运行：

```bash
npm run start:env
```

普通 `npm start` 读取进程环境变量，**不会自动加载 .env 文件**。

| 变量           | 默认值      | 用途                                         |
| -------------- | ----------- | -------------------------------------------- |
| PORT           | 3000        | HTTP 端口                                    |
| HOST           | 0.0.0.0     | 监听地址；仅本机使用可设为 127.0.0.1         |
| OPENAI_API_KEY | 空          | 可选的服务器共享密钥                         |
| OPENAI_MODEL   | gpt-4o-mini | 未指定模型名时使用的模型；需账号具有访问权限 |

即使服务器有 Key，默认仍是本地模式。请勿将 .env 提交到 Git。

## Docker 部署

```bash
docker build -t tongti .
docker run --rm -p 3000:3000 tongti
```

需要环境变量时：

```bash
docker run --rm -p 3000:3000 --env-file .env tongti
```

容器以非 root 用户运行，自带健康检查 /api/health。外网部署时在前面配置 HTTPS 反向代理。

当前版本使用**单进程内存房间**：请只运行一个实例，或保证同一房间始终路由到同一实例。容器重启、休眠回收或进程重启都会清空房间。不要将此版本直接部署为会随请求创建/销毁进程的无状态函数。

## 数据与边界

- 每个房间最多 2 人、20 轮；从创建起固定保留 24 小时，过期清理。
- 最多 1000 个活跃房间；题目 500 字、回答 4000 字、最多 8 个选项，每项 120 字；请求体最多 32 KiB。
- 会话凭证放在当前标签页的 sessionStorage，不放在邀请链接里。关闭标签页或清理存储后可能无法找回身份；保留原标签页，必要时另开新房间。
- “返回首页”不会释放已有席位；在原标签页再次访问邀请链接可恢复。没有账号系统或找回机制。
- 邀请链接相当于入场凭证，应发给想邀请的人；谁先加入就占据第二个席位。
- 未加入者只能看到房间人数和分析方式；参与者接口使用随机会话令牌鉴权，不能用昵称冒充对方。
- 无数据库、无永久云端历史、无访客追踪；可自行下载讨论记录。
- 创建房间每个直接连接 IP 每小时最多 20 次，其他写操作每分钟最多 120 次。限流不信任 X-Forwarded-For；反向代理后的访问会共用代理 IP 配额，公开服务应在可信网关另配限流。
- API 和房间读取禁止缓存；静态资源使用 MIME 类型白名单，配置 CSP 与 nosniff。

```bash

npx playwright install chromium
npm run test:e2e
```

- npm test：18 项 Node 单元与 HTTP 集成测试，验证双人完整流程、盲答、鉴权、输入校验、重复提交、超时回退、房间过期与容量边界。
- npm run test:e2e：Chromium 桌面和手机布局，验证两位独立用户的加入、揭晓、刷新、导出、多轮、网络恢复与错误提示。

- 模型接口测试使用可控模拟响应，**不消耗真实 API 额度，也不证明真实账号的密钥、模型权限或网络可用性**。需要真实 Key 才能完成实际模型验收。
- Dockerfile 已提供；是否成功构建、外网可达仍需在实际部署环境验证。

## API（v2）

创建或加入成功返回 token，后续参与者请求携带 `Authorization: Bearer <token>`。

| 方法与路径                 | 功能                                                                          |
| -------------------------- | ----------------------------------------------------------------------------- |
| GET /api/health            | 健康检查                                                                      |
| GET /api/preset-questions  | 题库                                                                          |
| POST /api/rooms            | 创建：nickname、question: { questionText, options }、可选 apiConfig / consent |
| GET /api/rooms/:id         | 无凭证为最小房间预览，有凭证为本人视角的状态                                  |
| POST /api/rooms/:id/join   | 加入：nickname、AI 房间需要 consent: true                                     |
| POST /api/rooms/:id/submit | 提交：round、answerText 和/或 selectedOption                                  |
| GET /api/rooms/:id/result  | 受鉴权保护的状态查询，与带凭证的房间读取一致                                  |
| POST /api/rooms/:id/next   | 房主开启下一轮：当前 round、新 question                                       |

round 防止网络延迟造成旧答案写入新题。同一轮第一次有效提交后锁定，重试返回现有状态。

v2 有意替换了旧版“自行填写房间号、用昵称提交”的接口；旧页面或旧 API 客户端需要更新。部署时同时更新前后端。
